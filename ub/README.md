# utility-bar

A drop-in top bar for the9ines sites, built as a **frame + snap-in pieces**. The frame
is a thin black strip; each feature is its own file you include only where you want it:

| piece | file | what it adds |
|---|---|---|
| **frame** | `utilbar.js` | the strip + a left/right area + the plugin API. Always included. |
| **theme** | `theme.js` | the colourway engine — recolours the whole page, remembers the pick. Standalone. |
| **colour** | `utilbar-colour.js` | the cookie + live colour tuner (drives `theme.js`). |
| **language** | `utilbar-language.js` | the language dropdown. |
| **search** | `utilbar-search.js` | a search box. |
| **status** | `utilbar-status.js` | an online/offline dot that pings your product's health. |
| **sign-in** | `utilbar-signin.js` | Sign in as a dropdown panel in the bar (no navigation), or a plain link. |
| **account** | *(built into the frame)* | the `extras` slot for a custom/account chip. |

A site that wants colour + accounts includes the frame, theme, and colour piece — and
nothing else loads. A docs site might take the frame + search + language. Pick per site.

CrumbProof (`crumbproof/public/index.html`) is the design source of truth. Improve the
look there first, then fold changes back into these files.

## Drop it in

Copy the folder into the project (e.g. `public/ub/`), set one config object, then include
the frame + the pieces you want:

```html
<script>
  window.UtilBar = {
    home: '/',
    colour: { icon: '/ub/icons/icon-{name}.svg', palette: [ /* … */ ] },
    signin: { label: 'Sign in', href: '/admin' }
  };
</script>
<script src="/ub/theme.js"></script>                <!-- colour engine: load SYNC in <head>, no defer -->
<script src="/ub/utilbar.js" defer></script>        <!-- the frame -->
<script src="/ub/utilbar-colour.js" defer></script> <!-- the pieces you want -->
```

> **Load `theme.js` synchronously (no `defer`), before the page paints.** It writes the colour at
> execution time, so a deferred engine paints the default first and then repaints — a visible flash.
> The bar **pieces** can and should keep `defer`; they inject after the DOM is ready and never flash.

**Or the easy way** — one bundled file with every piece (regenerated by `build.sh`):

```html
<script> window.UtilBar = { /* config */ }; </script>
<script src="/ub/bundle.js"></script>               <!-- sync = no flash; add defer only if a flash is fine -->
```

The bundle is simplest; the separate files let a site ship only the code it uses. But the bundle
carries the engine, so **defer it and the flash comes back** — a flash-sensitive site loads the
bundle synchronously, or keeps `theme.js` separate + sync and defers the rest. Same config either
way. Open `demo.html` for a full working example.

## Config

One `window.UtilBar` object. Every section is optional — leave it out and that piece does
nothing (and, with separate files, you just don't include it).

| key | piece | effect |
|---|---|---|
| `home` | frame | Where the brand/cookie (or a fallback "Home" link) points. Default `/`. |
| `order` | frame | Reorder the right-side pieces — a list of names, left→right (see below). |
| `colour` | colour | Palette + cookie/tuner. Needs `theme.js` + `utilbar-colour.js`. |
| `languages` | language | Array of `{code,label,href}`. Needs `utilbar-language.js`. |
| `allRegions` | language | Adds an "All regions →" link under the language menu. |
| `search` | search | `{placeholder, action:'/s?q={q}' or onSearch(q), width}`. Needs `utilbar-search.js`. |
| `status` | status | `{url, every, label, upLabel, downLabel}`. Needs `utilbar-status.js`. |
| `extras` | frame | Custom right-side items — the **account chip** lives here. |
| `signin` | sign-in | Sign in — a dropdown **panel** in the bar (`onSubmit`/`action`/`panel`), or a plain `href` link. Needs `utilbar-signin.js` for the panel. |

### `colour`

```js
colour: {
  accentVar: '--accent',                          // your page's accent var (theme also sets
                                                  //   --ub-accent/-deep/-ombre + --on-accent)
  icon: '/ub/icons/icon-{name}.svg',              // cookie image; {name} -> colourway name
  store: 'mysite-cw',                             // localStorage key for the remembered pick
  specimen: ['Consent', 'you', 'can', 'prove.'],  // tuner preview line (last word accented)
  inkDark: '#160f16', inkLight: '#ffffff',        // text-on-accent for dark/light accents (optional)
  paths: { '/': 'lagoon', '/login': 'neon' },     // optional per-page colour (see below)
  palette: [ ['berry', '#FF8DC5', '#FF8DC5', '#8C235A'], /* [name, accent, rampLight, rampDark] */ ]
}
```

Your page reads the accent as `var(--accent)` (or your `accentVar`); `var(--on-accent)` is the
readable ink on top of it (`inkDark`/`inkLight` override the defaults). The lone final chip
auto-centres when the count is odd on a 6-wide grid (e.g. 13).

**Per-page colour (`paths`).** By default every page opens in the first colourway until a visitor
picks one (which then sticks everywhere). Give `paths` a map and each listed page opens in its own
colour instead; any page not listed gets a stable per-URL colour. A saved pick still overrides all.
Omit `paths` and you get the single-colour default — per-page is opt-in.

### `search`

```js
search: { placeholder: 'Search docs', action: '/search?q={q}', width: 160 }
// or provide a handler instead of a URL:
search: { placeholder: 'Search', onSearch: function (q) { /* … */ } }
```

### `status` — "is the product up?"

```js
status: { url: '/api/health', every: 30000, label: 'CrumbProof', upLabel: 'Online', downLabel: 'Offline' }
```

Pings `url` on a heartbeat; an ok response is green "up", anything else is red "down". With
no `url` it reflects the browser's own online/offline state.

### `extras` / account chip

```js
extras: [
  { label: 'Docs', href: '/docs' },                                       // a plain link
  { html: '<a id="acct" class="ub-link" href="/account">Account</a>' }    // raw markup you control
]
```

For a **dynamic account chip**, pass an `{html}` placeholder with an id and paint it once
the bar exists:

```js
document.addEventListener('utilbar:ready', function () {   // fires after the bar is in the DOM
  var el = document.getElementById('acct');
  fetch('/api/me').then(r => r.json()).then(u => { el.textContent = u.email || 'Sign in'; });
});
```

The module owns the bar and gives you the slot + the `utilbar:ready` signal; your site owns
the auth. Same recipe for CrumbProof, aifreeware, localbolt.

### `signin` — sign in without leaving the page

With `utilbar-signin.js` included, `signin` renders a dropdown **panel** in the bar, so clicking
it never navigates — you keep the bar, the tuner, everything. Give it a handler and it collects
the fields for you:

```js
signin: {
  label: 'Sign in',
  onSubmit: function (creds, ui) {          // creds = {email, password}
    myAuth(creds).then(() => ui.close()).catch(() => ui.message('Wrong email or password.'));
  },
  forgotHref: '/forgot'                     // optional link under the form
}
```

`ui.message(text)` shows a line under the form; `ui.close()` shuts the panel. **Auth is yours** —
the piece collects the fields and hands them to `onSubmit`; it never sends credentials anywhere
itself. Other shapes: `action: '/api/auth/sign-in'` lets the default form POST there; `panel:
'<form>…</form>'` supplies your own markup (wire it on `utilbar:ready`); `href: '/login'` with
none of the above is a plain navigating link.

## Right-side order

By default the pieces sit **language → search → status → account → sign in**, stable no matter
which files load when. To change it, list the piece names left→right in `order`:

```js
window.UtilBar = { order: ['status', 'language', 'search', 'extras', 'signin'], /* … */ };
```

Names: `language`, `search`, `status`, `extras` (the account slot), `signin`. Anything you
leave out keeps its default spot, after the ones you listed. The colour cookie always holds
the left.

## Writing a new piece

A piece is a small file that reads its own config off `window.UtilBar` and mounts itself
through the frame's API:

```js
(function () {
  var UB = window.UtilBar; if (!UB || !UB.myThing) return;
  UB.css('.ub-mything{ /* … */ }');                 // inject its styles
  UB.ready(function () {                             // runs once the bar exists
    var el = document.createElement('span'); /* build it */
    UB.mount('right', el, 40);                       // add to a side, with an order weight
  });
})();
```

Frame API (on `window.UtilBar`): `ready(fn)`, `mount(side, node, order)`, `css(text)`,
`onBeat(fn, ms)` (the status heartbeat), `esc(s)`. Events on `document`: **`utilbar:ready`**
(bar built) and **`utilbar:colour`** (`{name, accent, iconUrl}`, on every colour change).
The engine is on `window.UBTheme` (`.set/.current/.clear/.list`).

## Adopting it on an existing site (hand-off checklist)

To swap a site's current bar for this module:

1. **Copy the folder in** — e.g. `cp -r ~/Projects/utility-bar <site>/public/ub`. Replace
   `icons/` with the site's own set (or point `colour.icon` at where its icons already live).
2. **Write the config** — the only per-site work. Different logos/icons are just the `icon`
   path; the module doesn't care what the art is.
3. **Include the frame + the pieces the site wants** (or `bundle.js`), then **delete the
   site's old bar** — its markup, CSS, and JS.
4. **Verify** (bar injects, tuner recolours the page, only the wanted pieces show) and deploy.

### Worked example: aifreeware.net

aifreeware has its **own hand-copied** `bar.js` + `theme.js`. To adopt this module: set a
config with `colour.icon: '/assets/favicon-{name}.svg'` (its own icons) and its 13-colourway
palette, no `languages`; include `theme.js` + `utilbar.js` + `utilbar-colour.js`; delete the
old `bar.js`/`theme.js` and the `.utilbar` markup. For its **account chip**, use `extras` +
the `utilbar:ready` event with aifreeware's existing `paintAccount()` logic.

## Files

- `utilbar.js` — the frame (strip + plugin API).
- `theme.js` — the colourway engine (standalone).
- `utilbar-colour.js`, `utilbar-language.js`, `utilbar-search.js`, `utilbar-status.js`, `utilbar-signin.js` — the pieces.
- `bundle.js` — all of the above in one file; regenerate with `build.sh` after edits.
- `demo.html` — a full working example.
- `icons/` — the 13 CrumbProof cookie SVGs, a starter set for `colour.icon`.
